# BiaPy 3.7.0 silent exit (2026-08-04)

Cursor chat writeup: empty SLURM logs after upgrading `BiaPy_env` to BiaPy 3.7.0, root causes, and fixes.

## Context

Goal: run config `BiaPy/configs/biapy-py_v1.yaml` through `sbatch/biapy/biapy-py_sbatch.sh` after upgrading the Singularity overlay conda env (`env/BiaPy_env.ext3`, env name `BiaPy_env`) from BiaPy **3.6.8** to **3.7.0**.

Submit pattern:

```bash
sbatch sbatch/biapy/biapy-py_sbatch.sh biapy-py_v1.yaml train
```

## Symptoms

Jobs such as **15272331** and **15273463**:

- State: `FAILED`, exit code `1:0`
- Elapsed: ~1–2.5 minutes
- `.out`: only the two sbatch echoes (`SBATCH Run: …`, `running BiaPy/run_biapy-py.py`)
- `.err`: empty (0 bytes)
- GPU util stayed at 0% for the whole short run
- MaxRSS ~3 GB (imports progressed far enough to load heavy deps)

`--help` on `run_biapy-py.py` inside the container exited 0 and printed usage. The real train path exited 1 with **no** console output.

## False leads (debugging detours)

These were real mistakes during diagnosis, not the underlying BiaPy bug:

1. **Nested `srun` inside a CPU interactive job** on `cs601` (job 15271636, partition `cs`) — `srun --gres=gpu:1 --constraint=…` failed with `Invalid feature specification`. GPU tests must run from a login shell *outside* that allocation, or via a fresh `salloc`/`sbatch`.
2. **Host `python3` vs container** — running `python3 BiaPy/run_biapy-py.py` on the node outside Singularity hit `SyntaxError` on `match` (host Python older than 3.10). Container env is Python **3.11.15**.
3. **Host `LD_PRELOAD` with empty `CONDA_PREFIX`** — `export LD_PRELOAD=$CONDA_PREFIX/lib/libstdc++.so.6` on the host became `/lib/libstdc++.so.6`, causing repeated `ld.so: … cannot be preloaded` warnings. Preload must be set **inside** the container after `conda activate`.
4. **Shell quoting** — multiline `python3 -c` pastes produced `IndentationError` / line-wrap `SyntaxError`. Prefer an interactive Singularity shell or a heredoc.

Interactive GPU tests that *did* work (import only):

```text
torch.cuda.is_available() → True
from biapy import BiaPy → ok
```

with `LD_PRELOAD=$CONDA_PREFIX/lib/libstdc++.so.6` inside the container.

## Root causes

Three separate issues stacked after the overlay upgrade.

### 1. BiaPy 3.7.0 swallows init output (`verbose=False`)

`BiaPy.__init__` gained a `verbose` parameter defaulting to **`False`**. During construction it replaces `sys.stdout` / `sys.stderr` with an in-memory buffer (optionally teeing to console only when `verbose=True`). Streams are restored only at the **end of a successful** `__init__`, with **no `try/finally`**.

Any exception during construction writes its traceback into the discarded buffer. The process exits 1 printing nothing — which is why SLURM `.out`/`.err` looked empty.

BiaPy’s own CLI sets `verbose=True`. The library Python API docs recommend quiet construction by default.

### 2. Config passed as `PosixPath` (actual crash)

`BiaPy/run_biapy-py.py` passed:

```python
config=CONFIG_DIR / args.config_file  # pathlib.Path
```

In 3.7.0, `_load_raw_config` accepts only `str`, `dict`, or YACS `CfgNode`. A `PosixPath` raises:

```text
TypeError: 'config' must be a path to a YAML file (str), a dict or a YACS CfgNode.
```

That exception was raised *after* the stream swap and *before* restore — so it was invisible until `verbose=True`.

Config backup also only runs when `isinstance(config, str)`, which matched empty `config_files/` dirs from failed runs (directory created, file never copied).

### 3. scipy / libstdc++ ABI mismatch

Newer scipy in the upgraded env (C++ extension `_distance_pybind`) requires symbol version **`CXXABI_1.3.15`**. The CUDA Singularity image’s system library `/lib/x86_64-linux-gnu/libstdc++.so.6` is too old.

Without a fix:

```text
ImportError: /lib/x86_64-linux-gnu/libstdc++.so.6: version `CXXABI_1.3.15' not found
```

Import path: `from biapy import BiaPy` → skimage → scipy.

Conda provides a new enough runtime at:

```text
$CONDA_PREFIX/lib/libstdc++.so.6 → libstdc++.so.6.0.35
```

Putting **all** of `$CONDA_PREFIX/lib` on `LD_LIBRARY_PATH` can break CUDA (silent hard abort). Preload **only** conda’s `libstdc++.so.6`.

## Fixes applied

### `BiaPy/run_biapy-py.py`

- Resolve config once as a string before the `match` on mode:

```python
config_path = (CONFIG_DIR / args.config_file).as_posix()
```

- Pass `config=config_path` and `verbose=True` on all three `BiaPy(...)` calls (`preprocessing`, `train`, `test`).

`update_config` / `train()` / `test()` exist in 3.7.0 and remain the intended train/test API.

### `sbatch/biapy/biapy-py_sbatch.sh`

- After `conda activate BiaPy_env`, set:

```bash
export LD_PRELOAD="${CONDA_PREFIX}/lib/libstdc++.so.6${LD_PRELOAD:+:$LD_PRELOAD}"
export PYTHONUNBUFFERED=1
```

- Run `python3 -u BiaPy/run_biapy-py.py …`
- Move the `nvidia-smi` GPU logger **after** `job_name` / `mode` are set (previously wrote `gpu_biapy-py__.csv` because those vars were still empty).

## Why `LD_PRELOAD` fixes scipy

1. scipy’s C++ `.so` needs `CXXABI_1.3.15`.
2. Default linker resolution uses the container image’s older `libstdc++` → `ImportError`.
3. `LD_PRELOAD` forces conda’s newer `libstdc++.so.6` to load first so the required ABI symbols are present.
4. `${LD_PRELOAD:+:$LD_PRELOAD}` appends any existing preload (e.g. NVIDIA bits from `--nv`) instead of wiping it.

Do **not** export `LD_PRELOAD` on the host with an empty `CONDA_PREFIX`.

- Batch job **15282010** ran with a populated `.out` (train/val shapes loaded, model build, training iterations). Stderr had tqdm and an expected custom-channels `UserWarning` only.
